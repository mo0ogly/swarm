# Rustc intent producer — experimental scope

`cd01_capture_rustc_wrapper.py` produces **pre-exec** receipts for a proposed future C-D01 collection. It qualifies no binary, compiler, profile or graph and runs no tests itself. Cargo integration/config precedence, actual selected paths/proxies/interpreters and the main collection still need separate review/allocation.

The protocol receives compiler at argv[1], followed by arguments. `CD01_CAPTURE_DIR` must be an existing absolute private euid-owned directory; `CD01_SPACEGUARD_PATH` an absolute trusted executable guard selected by the coordinator. No configuration default, fallback, retry or timeout is introduced. The future collector owns volume identity, target admission, disk reserve, source stability and tool/interpreter hashes; this wrapper establishes none of them.

Each invocation exclusively creates a private directory. It fully writes ASCII JSON into `intent.partial`, fsyncs/closes it, then publishes a no-clobber hardlink `intent.json` and syncs the directory. The partial remains. Compiler/guard paths, arguments and cwd use reversible byte hex; the configured guard is explicitly retained. No arbitrary environment dump is recorded. Arguments may contain secrets: the caller must authorize/review the data; avoiding environment dumps does not guarantee argument secrecy.

After publication, `os.execv` attempts same-process replacement by `[guard, compiler, arguments…]`, leaving the environment unchanged. The receipt describes intent only, outcome UNKNOWN, never an observed execution chain. Held descriptors are CLOEXEC. Collisions refuse without overwrite/retry. Requested 0700/0600 modes remain subject to umask; access failures are refusals, never successful empty results.

On failure, partials remain and an exclusive `failure.json` is attempted. It describes the primary cause and known publication facts; cleanup causes reach the safe diagnostic. A visible link after fsync failure is neither declared durable nor rolled back. If stderr fails, `WrapperReportingError` retains primary and secondary causes, including reporting failure, in memory with a static message and suppressed displayed context. This does not guarantee durable receipts when all channels fail. Exit codes78/1/130 and schemas are technical conventions, separate from guard operator policy. Invalid configuration can also fail a system call and be classified operational failure.

Final-component no-follow/private permissions assume a stable caller lease, not same-UID adversarial confinement. There is no cleanup, configuration mutation or product installation.

## Packet20 library hook — explicit input lease

`main` accepts a keyword-only `stdin_lease` parameter. `None` with both operator manifest variables absent keeps the exact v1 protocol and record bytes without reading descriptor 0. The explicit pair can now select a lease as described below. An explicit lease is a trusted-caller library decision: an exact five-member mapping {allocation_id, input_fd, compiler_path_hex, compiler_arguments_hex, cwd_hex}, validated in full — shape and equality with argv[1], argv[2:] and the current working directory — before any byte is read and before any directory or record is created; any mismatch refuses (78). It is a declared finite cooperative single-writer input/privacy lease: not authentication, producer ancestry, future-EOF proof or OS confinement. No argv-minus/FIFO/env-token inference and no hardcoded producer/mission paths exist; the leased descriptor is borrowed by the capture, never auto-read.

The selected invocation keeps the existing exclusive directory and publishes a v2 pre-exec intent linking the allocation and the relative custody directory, with transfer status PENDING — never rewritten retrospectively, success is never retrospective. Only after the intent is durably published: private custody mkdir, lazy explicit-source load of the reviewed sibling `finite_input_custody.capture(input_fd, subdir, allocation_id)` (a missing module refuses the selected invocation, with no fallback lookup or installation; module dependency and toolchain provenance remain outer-collector qualification), registration of the returned O_RDONLY descriptor in the existing close-once custody, explicit inheritable dup2 onto 0, single spare close, exclusive stdin-transfer receipt under the invocation directory (observed input digest reported by the manifest, count/linkage, replacement and spare-close attempt/completion, exec UNKNOWN). The receipt never proves compiler consumption. Any capture/dup2/close/publication failure means no exec and no consumed-input fallback; a successful dup2 may already have replaced 0, that state is retained as observed, and rollback is never inferred. Failure-state booleans report observed attempts/completions, never an inferred no-effect.

This library hook preceded the operator manifest selection of packet23 below: no Cargo wiring, build allocation or qualification is claimed here. The current collector run/CLI refuses v2 without a validator, while its packet21 library reader accepts v2 with an explicit callback; that is expected, not a defect. The existing capture29 proof scope is reused unchanged; the seven producer guards stay without a global replay; the recipe lists the full name set and count, but the root run covers only the new guard class.

## Operator manifest selection (packet23) — wrapper CLI only

The CLI entry point now accepts the optional pair `CD01_STDIN_LEASE_MANIFEST` (absolute byte path) and `CD01_STDIN_LEASE_MANIFEST_SHA256` (exactly 64 lowercase ASCII hexadecimal digits). Both absent keeps the exact v1 protocol and record bytes; a partial pair refuses (78); the pair combined with an explicit library `stdin_lease` argument refuses before any capture, record creation or descriptor-0 read. The manifest is opened once O_NOFOLLOW|O_CLOEXEC readonly, must be a private effective-uid-owned regular file (fstat), is read fully with no size cap and no import fallback, and its descriptor is then closed exactly once through the existing close-once custody before any parsing — no leak on refusal, no double close. The SHA-256 of the exact read bytes is compared before any JSON parse; a mismatch refuses. The loader's read window is this one file only; the descriptor-0 read window remains the reviewed custody helper's finite read-until-EOF behavior.

The document must be the exact `cd01.stdin_lease_manifest/1` protocol: top members exactly {schema, record_kind, leases}, record_kind `operator_stdin_lease_manifest`, and a `leases` list (empty allowed) whose every entry is exactly {allocation_id, input_fd, selector, declarations, repeat_policy} — a nonempty unique allocation_id string, input_fd the exact integer 0 (never bool), repeat_policy the literal `repeatable` only, declarations {finite_cooperative_single_writer_input, producer_will_close_input_fd, persistence_authorized} all the boolean true (never the integer 1), and a selector {compiler_path_hex, compiler_arguments_hex, cwd_hex} of lowercase even-length hex decoding to NUL-free bytes with a nonempty path and cwd; the argument list may be empty and may contain empty arguments. No operator name, mission or date policy exists in the protocol. Duplicate JSON members refuse, duplicate allocation ids refuse, duplicate exact selector tuples refuse even with distinct allocation ids, and every entry is validated before any selection.

An entry whose selector equals this invocation's argv[1] compiler bytes, argv[2:] argument bytes and current working directory yields the existing five-member lease and drives the reviewed v2 flow (real sibling helper load, custody, dup2, exclusive receipt); no match keeps exact v1 and never reads descriptor 0. Exact invocation byte equality is not source identity, ancestry, a future-EOF proof, confidentiality against the same UID or native proof; eligibility is never inferred from a '-' argv, crate names, rustix or source text, and the finite/single-writer/privacy declarations remain caller preconditions. Every invocation loads and selects independently, with no shared counter, lock, global state or single-use marker; repeated exact invocations each receive their own exclusive receipts. Malformed schema/hash/type refuses (78); open/read/close errors keep their original errno as operational failure (1); interrupts stay 130 through the existing `_handle_failure`; an unreadable or malformed manifest never falls back implicitly and no raw manifest text, digest or diagnostic value is echoed; recovery is a corrected re-invocation with no cleanup or rollback. The current collector can neither stage the helper or the manifest nor consume this CLI; full helper wiring and actual compiler consumption remain future.
