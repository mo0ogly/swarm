## Proposal

Add a third case function to `tests/rust_native_web_conductor.py` (called from `main()`'s `cases()` after `held_planner`, in a fresh output root). No new module, no product code changes, no opaque task ordering — turn order is observed from the public queue DTO, never assumed.

    """Second turn only after first server stop, lease release and helper reap."""
    out.mkdir(parents=True, mode=0o700, exist_ok=False)

        # and release via fixture.publish(release-worker.json) + waitpid. Task 'task'
        # remains 'blocked' per run() evidence; agent status 'completed'.

## Turn ordering (observed, not guessed)

1. **Turn one start**: `before_worker=True` flow with `return_fixture=True` gives a ready task (`status='READY_FOR_NATIVE_WORKER'`) — same as `run()`.
2. **Hold**: helper admitted via `public.attach_provider`; `worker.supervision(f)['stopped_at']==''`.
3. **Stop**: authenticated HTTP `stop` (`control('stop', ...)`); assert `stopped_at != ''` and helper reparented (`observation(ppid)==os.getpid()`) — exactly `run()`'s shutdown evidence.
4. **Release/reap**: publish `release-worker.json`, `waitpid` the helper to exit 0; optionally `public.reap_cleanup_helper` on failure cleanup only.
5. **Turn two reopen**: fresh `native.Server` on same root; consent already False and prior completed agent retained (per `run()`'s reopen and `identity-recovered` cases). A new start then admits a second independent worker.
