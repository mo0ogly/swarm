## 5. Mécanismes d'échec les plus coûteux (observés)

1. **Inertie du dialog modal natif** (2 itérations UI) : les gestes header et
   les boutons dans `<details>` fermé ne se déclenchent pas depuis le harnais
   comme depuis un utilisateur. Cause observée par différence ; hypothèse de
   portée exacte (focus vs inertie) non discriminée.
2. **State trust réel non configuré** : l'administration BLP positive n'est pas
   observable sur la racine réelle sans bootstrap trust (création d'identités
   réelles). Ce n'est pas un défaut produit ; c'est une précondition opérateur
   restée hors périmètre autorisé. Reprise : décision utilisateur + procédure
   de bootstrap, puis requalification positive.
3. **Sortie de tâches du harnais sous `/tmp`** : la règle utilisateur interdit
   `/tmp` ; détection à l'arrêt de la première tâche, redirection immédiate.
   Vérification : le build/restart utilisent des logs dans le dépôt.
4. **Collision concurrente sur `version_history.json`** : une session tierce
   a reconstruit/installé v0.1.1-dev.283 pendant la qualification et écrasé
   l'entrée BLP (préuve : leur `effective-sources.tar.gz` sans item BLP).
   Réinsertion atomique sur leur état, les deux entrées coexistent ; le
   serveur 283 sert le routage BLP (sonde identique) ; la note BLP passera
   au prochain build. Apprentissage capitalisé dans la mémoire de session
   (travaux concurrents sur version_history : relire avant append et
   revérifier après build tiers).
