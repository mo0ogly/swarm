## 5. Mécanismes d'échec les plus coûteux (observés)

1. **Attente UI satisfaisable en vol** (~2 itérations) : les états
   intermédiaires (bouton désactivé par `guarded()`, texte de statut antérieur)
   satisfont un `waitForFunction` pendant la requête ; Escape fermait alors le
   dialogue et la restitution de focus visait un bouton encore désactivé.
   Correctif général : n'attendre que des effets posés après la relecture
   interne. Vérifiable par construction pour les prochains parcours.
2. **Contrôles muets hors dialog modal** (1 itération) : les contrôles dans un
   `<details>` fermé acceptent le clic sans effet ; ouverture préalable
   exigée — déjà connu du RETEX 31/10, réapparu sur une nouvelle surface.
3. **Un objet unique pour huit parcours** (1 itération) : le producteur
   refuse un second enregistrement du même triplet (exact-once, attendu) — le
   pilote devait créer un objet distinct par combinaison FR/EN×thème×largeur.
   Conception du test, pas un défaut produit.
4. **Contrat pilote incomplet** (`public_output`, portée des drapeaux) :
   deux itérations perdues sur des défauts du harnais de test lui-même ; le
   précédent établi (`blp_quarantine_ui.cjs`) n'avait pas été consulté avant
   l'écriture.
5. **Dérive de traçabilité** (`version_history` sans entrée BLP-03a) :
   découverte au RETEX, pas à la livraison ; la règle « documentation dans le
   même incrément » a tenu pour les plans mais pas pour le registre de
   versions. Correctif appliqué (diff +4 lignes).
