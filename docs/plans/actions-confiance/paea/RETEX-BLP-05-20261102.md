## 5. Mécanismes d'échec les plus coûteux (observés)

1. **Sémantique de renouvellement de politique mal anticipée** (~4 itérations
   du parcours) : après tout changement de révision de confiance, l'entrée
   politique ancienne devient inutilisable pour `current()` jusqu'à
   renouvellement explicite ; le rejet se manifeste en amont
   (`blp-policy-stale`) avant même la classification. Coût : itérations du
   parcours au lieu d'une sonde préalable — corrigé en sondant, puis en
   insérant le troisième `blp-policy-apply`.
2. **Garde anti-déclassification à portée totale de l'historique** : un rebond
   public d'un digest déjà lié secret refuse pour toujours ; le test
   no-write-down a dû être restructuré autour d'un second connecteur (digest
   frais) plutôt que d'un rebond public du digest lié. Détection en exécution,
   pas en conception.
3. **Helpers de requête avec champs implicites** : `TypeError: dict() got
   multiple values for keyword argument` — champs surchargeables passés en
   paramètres nommés explicites ; vérification AST pour exclure les doublons
   réels.
4. **Fuite producteur `/tmp`** (héritée, non de cette session) :
   `preparation_calls.rs` dépendait du `TMPDIR` par défaut ; découverte lors
   du contrôle de propreté, correction sur le schéma établi, garde de
   régression = le test lui-même échoue maintenant hors zone de fixtures.
5. **Classifieur auto-mode indisponible** (refus répétés, dont sur `rm`) :
   attente lecture seule puis transmission de l'action `rm` à l'utilisateur,
   qui l'a exécutée ; aucune reprise aveugle de l'action refusée.
