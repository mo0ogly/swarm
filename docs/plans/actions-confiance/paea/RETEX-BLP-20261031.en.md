## 5. Most costly failure mechanisms (observed)

1. **Native modal dialog inertness** (2 UI iterations): header gestures and
   buttons inside a closed `<details>` do not fire from the harness the way
   they do for a user. Cause observed by difference; the exact scope
   hypothesis (focus vs inertness) is not discriminated.
2. **Real trust state unconfigured**: positive BLP administration is not
   observable on the real root without a trust bootstrap (creating real
   identities). Not a product defect; an operator precondition left outside the
   authorized scope. Recovery: user decision + bootstrap procedure, then
   positive requalification.
3. **Harness task output under `/tmp`**: the user rule forbids `/tmp`;
   detected when stopping the first task, redirected immediately.
   Verification: build/restart use in-repo logs.
4. **Concurrent collision on `version_history.json`**: a third-party session
   rebuilt/installed v0.1.1-dev.283 during qualification and dropped the BLP
   entry (proof: their `effective-sources.tar.gz` contains no BLP item).
   Atomic re-insertion on top of their state, both entries coexist; server 283
   serves the BLP routing (identical probe); the BLP note lands in the next
   build. Lesson capitalized in session memory (concurrent work on
   version_history: re-read before append and re-check after third-party
   builds).
