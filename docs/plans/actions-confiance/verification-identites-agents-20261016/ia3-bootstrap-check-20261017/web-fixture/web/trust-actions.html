        ADMINISTRATION
        Configurer le pilote
        Prévisualisez les valeurs et les identités avant de les appliquer. Les jetons ne seront ni affichés ni conservés en clair.
        Chaque configuration appliquée impose de renouveler les mandats avant une nouvelle demande, approbation ou un premier engagement. Les effets déjà engagés restent réconciliables.
        0 désactive les délégations. Chaque mandat enfant nécessite un administrateur I3 et ne peut élargir les droits du parent.
        Accès des identités
        Décochez une identité pour suspendre ses opérations. Les actions et preuves sont conservées.
        Connexion d’entreprise OIDC
        Le compte externe est associé explicitement à une identité locale. Ses groupes ne donnent aucun droit automatiquement. Les durées sont en secondes ; 0 est refusé.
        Courtier de secrets éphémères
        Canal limité au helper interne ; aucun secret dans les preuves ou les réglages. Les fournisseurs externes restent non qualifiés.
        0 est refusé. L’octroi ne peut pas durer plus longtemps que la matière. La limite technique de transport est de 1 Mio. L’arrêt du serveur perd les matières ; les anciens octrois restent inutilisables.
        

        Diagnostic noyau
        0 est refusé. Le ring doit être une puissance de deux. L’aperçu ne lance rien ; une expiration termine le groupe du helper. Aucun privilège Linux n’est ajouté.
        Observation des agents
        Valeurs positives ; 0 est refusé. La fenêtre doit être inférieure au délai total. Aucun lancement automatique ni nouvelle mission. L’aperçu ne lance rien.
        Vérifications de confinement
        0 est refusé. Une expiration interrompt le groupe du processus de contrôle. L’aperçu ne lance aucun processus.
        Politique des données
        Les fournisseurs externes, fichiers et URL arbitraires restent refusés.
        Chaque liste est un tableau JSON explicite. Une liste vide refuse toute nouvelle action. Sans contrôle actif, le pilote historique reste utilisable sans qualification pour les données sensibles.
        Chaque ressource exige une règle exacte, par exemple [{"resource":"invoice/acme","classification":"internal"}]. Une déclaration du demandeur ne peut pas déclasser la ressource.
        Actions métier : public/internal sur les chemins locaux disponibles. Matière secrète : restricted/local-attestation/swarm/sealed-attestation, uniquement vers le helper fixe.
        Les listes actives s’appliquent aussi au chargement et à l’octroi de secrets. La classification restricted est imposée à la matière ; les ressources de l’action restent classées séparément.
        Groupes et rôles locaux
        Les groupes signés des personnes et des services sélectionnent uniquement des rôles déjà autorisés localement. Un claim absent, invalide ou sans rôle effectif refuse la connexion. Les jetons locaux restent distincts.
        Exemple : [{"group":"finance","roles":["approver"]}]. Les rôles locaux possibles sont requester, approver, effect et admin. Une modification invalide les sessions et nécessite de renouveler les mandats.
        Authentification renforcée des approbations
        Une preuve OIDC récente et liée au contenu exact est requise pour approuver. Les jetons locaux et les services ne la remplacent pas.
        Opération protégée : approbation exacte. Le sens des ACR doit être convenu avec votre fournisseur d’identité.
        Un âge de 0 impose une nouvelle authentification. La durée de preuve doit être strictement positive et ne dépasse pas celle de la session ou du jeton fournisseur.
        Déconnexion par le fournisseur OIDC
        Un événement signé retire les sessions humaines concernées. Les services et les effets déjà engagés sont conservés.
        0 conserve les empreintes sans purge. Une durée positive doit couvrir l’âge maximal. Une empreinte est toujours conservée au moins jusqu’à l’expiration du jeton signé.

        Identités de services
        Enregistrez uniquement les clés publiques des services. Chaque client est associé à une identité locale. Les durées sont en secondes ; 0 est refusé.
        Révocation des services
        Vérifier le jeton auprès de son émetteur à chaque usage, sans cache. Enregistrez la clé publique du serveur chez cet émetteur avant la connexion. Un redémarrage exige une nouvelle clé et une nouvelle connexion.
        Valeurs entières positives ; 0 est refusé. La fenêtre borne la décision locale, sans garantir une révocation instantanée entre deux systèmes. Les sessions en mémoire sont perdues à l’arrêt.
