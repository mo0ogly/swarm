# F5 · Systeme design — Portail client Swarm

Fondation dependant de F4 (architecture backend acceptee). Objet : fixer un systeme
design candidat traca ble aux sept stories de F2, couvrant visual_direction, tokens,
components, screens, responsive, accessibility, i18n, states, avec decisions et
limites explicites. Produit : `docs/portal-client-swarm/F5.spec.json` (contenu
original complet, declare en preuve de livraison) + ce rapport.

## 1. Direction visuelle

Produit vitrine d'un moteur deterministe, pas un decor. Palette neutre (clair/sombre
complets, bascule obligatoire pour cet increment, cf decision D-F5-1), accent reserve
aux actions et etats, police systeme uniquement (pas de dependance CDN tierce hors
perimetre, decision D-F5-2). Typographie monospace reservee aux identifiants/JSON/
journal d'audit pour marquer la frontiere entre texte produit et preuve technique.
Aucune animation decorative non fonctionnelle ; transitions d'etat courtes (<=200ms),
jamais sur un message d'erreur/refus (lecture immediate prioritaire sur l'esthetique).

## 2. Tokens

Couleur (paires light/dark avec regle de contraste AA minimum), typographie (echelle
xs->2xl, police systeme sans-serif pour l'UI et monospace pour le technique), espacement
(echelle multiples de 4px), rayon de bordure (sm/md/lg), elevation (0/1/2) et motion
(120/200ms, ease-out). Detail complet dans `F5.spec.json.tokens`. Regle explicite :
un seul niveau de titre par ecran, 16px de marge interne par defaut des cartes.

## 3. Composants

Onze composants couvrant les sept stories :

| Composant | Story(ies) | Points cles |
| --- | --- | --- |
| AppShell | toutes | 3 variants (public/client/admin), navigation admin re-verifiee serveur |
| GraphProofViewer | decouverte | lecture seule, 4 etats, jamais de stacktrace en erreur |
| ModelCard | catalogue | liste/comparateur/fiche ; aucun POST moteur avant connexion |
| AuthForm | sessions | login/register, message generique identique E8/D-F3-2 |
| ResourceList | ressources | re-verification serveur a chaque acces detail, jamais de cache non confirme |
| OnboardingStepper | demarrage | reprise exacte current_step, etape bloquee preservee sur E7 |
| AdminAccountSearch | administration | visible seulement si role admin confirme serveur |
| AdminAccountDetail | administration | transaction effet+audit, pas de modif partielle silencieuse |
| AuditLogTable | administration, revocation | tri decroissant, reserve admin (D5=A1 F4) |
| ConfirmDangerDialog | revocation | jamais de succes affiche avant reponse serveur 200 (anti succes-degrade) |
| StatusBanner | toutes | alerte session expiree/refus en navigation |

Detail variants/etats complet dans `F5.spec.json.components`.

## 4. Ecrans (FR/EN, mobile/desktop)

Douze ecrans couvrant les sept stories, chacun relie a ses composants, a sa regle
FR/EN et a son comportement responsive (detail dans `F5.spec.json.screens`) :

- **decouverte** : SCR-public-landing (graphe exemple + texte, 2 colonnes desktop / empile mobile).
- **catalogue** : SCR-public-catalog (grille ModelCard, comparateur side-by-side desktop / empile mobile), SCR-model-detail.
- **sessions** : SCR-login, SCR-register, SCR-client-home.
- **ressources** : SCR-resources (maitre-detail desktop / deux pages mobile), SCR-resource-detail.
- **demarrage** : SCR-onboarding-guide (stepper lateral desktop / horizontal compact mobile).
- **administration** : SCR-admin-search (tableau desktop / cartes mobile), SCR-admin-account-detail.
- **revocation** : SCR-admin-audit-log (tableau desktop / cartes empilees mobile), action de revocation portee par AdminAccountDetail + ConfirmDangerDialog.

Chaque story du plan (decouverte, catalogue, sessions, ressources, demarrage,
administration, revocation) a au moins un ecran et un composant associe : couverture
verifiee structurellement par le controle ci-dessous (section 8), pertinence
semantique renvoyee a la revue independante (cf limites).

## 5. Responsive

Breakpoints mobile <768px / tablet 768-1023px / desktop >=1024px. Regles fermes :
tout tableau (audit, resultats admin) a un equivalent carte sous 768px ; toute vue
maitre-detail devient navigation deux pages sous 768px ; cibles tactiles >=44x44px ;
aucune information uniquement au survol (equivalent focus/tap obligatoire).

## 6. Accessibilite

Cible WCAG 2.1 AA. Navigation clavier complete (Tab, Entree/Espace, Echap sur
dialogues), focus visible systematique (token `focus_ring`, jamais `outline:none`
sans remplacement), roles ARIA cles (ConfirmDangerDialog = alertdialog avec focus
initial sur l'action la moins destructive, StatusBanner danger = alert, stepper
avec aria-current), labels de formulaire toujours visibles (jamais placeholder
seul). Contraste vise par construction des tokens, verification manuelle/outillee
renvoyee a la realisation (limite explicite, aucun outil execute dans ce perimetre).

## 7. I18n et etats

FR/EN par dictionnaire de cles statique, couverture obligatoire de toute chaine
visible (y compris messages generiques d'erreur et libelles d'enum), horodatages
non ambigus. Quatre etats systematiques par ecran a donnees : loading (squelette
fidele a la forme finale), empty (message + action suivante utile, jamais traite
comme une erreur), error (message generique sans detail technique interne, refus
d'autorisation distingue explicitement d'une panne reseau), success (confirmation
uniquement apres reponse serveur effective, jamais optimiste pour une action
destructive — directement lie a l'exigence anti succes-degrade de F2/F3/F4 sur
la revocation).

## 8. Decisions ouvertes tranchees dans ce perimetre

- **D-F5-1** — Theme clair/sombre : obligatoire au premier increment (deja requis
  par le cadre de verification de la tache), pas une extension differee.
- **D-F5-2** — Police : systeme uniquement, aucune police web externe (coherent
  avec l'interdiction de connexion reseau distante additionnelle du perimetre agents).
- **D-F5-3** — Maquette HTML/SVG executable : non produite dans ce depot pour cet
  increment ; la specification structuree (tokens/composants/ecrans) est jugee
  suffisante pour deriver une maquette en realisation, dans le budget d'outils
  restant reserve aux verifications et au rapport.

## 10. Limites

- Aucune maquette HTML/SVG executable livree (D-F5-3) ; aucun code moteur, aucune
  publication, aucun effet externe.
- Contraste des tokens vise AA par construction mais non verifie par un outil
  automatique dans cette tache.
- Pertinence semantique du mapping story -> ecran -> composant reservee a la revue
  independante ; les controles locaux ne verifient que structure/longueur.
- Theme clair/sombre persistant par compte suppose un champ de preference non encore
  present dans `data_model.Account` de F4 ; a ajouter en realisation si confirme.
- Dictionnaire de traduction FR/EN complet non livre ici ; seule la regle de
  couverture (une cle par chaine visible) est fixee.
