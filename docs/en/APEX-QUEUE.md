## Prepare the next entry with APEX

On resumption, open the source plan and read its current state. Source changes
prevent automatic reuse of the state displayed here. Preserve existing IDs,
history, consumption, refusals and evidence.

The next increment's brief must identify:

- **Need and source**: observable objective, requirement IDs and canonical plan;
  separate verified work, partial work and proposals.
- **Scope and dependencies**: bounded outcome, exclusions, prerequisites and
  connections to other plans; do not adopt an entire roadmap at once.
- **Ownership**: integration owner, implementer and assigned files; independent
  review in another context when required.
- **Authority and resources**: applicable start decision, actual rights,
  providers and budgets; a role name never establishes capability.
- **Verification and recovery**: valid control, refusal without mutation,
  failure, reopening and observed effects as applicable; `replan` on anomalies.
- **Closure**: exact candidate and inputs, checks actually executed, required
  verdicts, FR/EN documentation and retrospective. Local evidence replaces
  neither independent acceptance nor policy-required human validation.

**Analysis → bounded plan → prerequisite and authority checks → authorized
execution → verification and review → retrospective and closure.** This is the
method, not a command or a new public Swarm status.

## Maintain the queue

Register labels distinguish proposal, waiting for prerequisites, technically
ready, authorized, in progress, locally verified and closed. Ready does not mean
authorized. Deferral preserves cause, owner and resumption condition; failed
verification keeps the criterion open.

Update the source plan and evidence, then this FR/EN summary in the same
increment. Actual progress depends on the public journey and applicable
evidence; this document is not an automatic scheduler and defines no concurrency
cap, deadline, budget or new engine policy.

Chosen approach: a register linked to plans rather than copied plans or native
missions created to represent them. This preserves history and makes dependencies
visible without launching additional work.

The queue is linked from both README files and after-cutover tracking. It carries
organization to later readers without changing running agent contexts, native
state, code, builds or delivered versions. This increment checks links, consistency
of the entries and their diffs.

separates G7 parity from Identity target closure, then IA3 authority → M20 uses
