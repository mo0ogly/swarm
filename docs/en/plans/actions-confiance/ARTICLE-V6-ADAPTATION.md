## P3 lease contract — planned, not implemented

Read sources: signed `Identity::expires_at` is checked before/after callback;
`paea_git_agreement_match` checks the mandate at read time; delegation narrowing
requires a child to expire no later than its parent. The reference runner checks
a supplied monotonic deadline before COMMIT bytes, but nested ordinary Git reads
currently receive only the persisted operator timeout.

Planned contract: under the existing shared lock, retain the earliest signed
authority/validated mandate expiry; map UTC to monotonic time without renewed
validity after a wall-clock rollback. Every relevant Git command must use the
earlier lease or persisted operator deadline, with no fixed margin/default.
Recheck admission before Commit decision and after nested reads; never restart
the lease duration. Late possible effects keep unknown/known observations.
Reconcile remains independently authorized read observation.

Injected-clock guards must cover future/past/exact expiry, UTC rollback, monotonic
expiry, forward UTC expiry, mandate/authority minimum, operator/lease minimum and
representation errors with retained causes. Test dates/durations are scenario
inputs, not product policy. A fresh native fixture remains necessary.

A client deadline cannot guarantee Git publishes before expiry after receiving
COMMIT: scheduling, suspension and storage can delay the effect. This protocol
currently carries no receiver-enforced authenticated lease at the effect point.
The planned lease bounds controlled admission/waiting under explicit clock
assumptions, not physical publication time. Stronger PA/H2 claims require an
effect-point receiver contract and its assumptions; a timeout or green test
cannot supply that proof. This remains open for the article.

P3 producer clarification: repository preparation already runs a bare-Git
check before returning, and candidate inspection composes further observations.
The proposed lease must not be described as a watchdog over the entire callback
or FS/SQL locks. After slow preflight, an already expired absolute validity
forbids the transaction; remaining-time calculation cannot mint a new lifetime.
The reference runner and its prepared-lock nested read are the explicit deadline
connection points, while upstream operation limits remain separately qualified.
