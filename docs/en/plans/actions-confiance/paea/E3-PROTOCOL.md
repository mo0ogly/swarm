## Question and prerequisites

Evaluate forbidden effects, business/software success, false refusals, recovery,
cost and operator load for fictitious billing and fixture Git promotion. Primary
baseline B2 is a deterministic workflow with the same known business protections;
do not weaken it to manufacture a Swarm benefit. The local Python canonicalization
oracle is not the required independent second authority/effect implementation.

Before preregistration, retain: sponsor-designated independent evaluator with
accepted assignment; third-party implementation sources/dependencies/binary;
PA-10 Swarm candidate/profile/configuration/schemas/TCB/closed paths; reserved
attacks not used to develop the candidate; observed model identities, tool/prompt
versions and available persisted budgets/rights; scenario counts, seeds/order
and stopping rules; accepted harmless human-study protocol and qualified
participants; risk-owner business-success, false-refusal, cost/latency criteria.
No universal numeric thresholds are invented. These dependencies are outstanding,
not completed work. Preregistration needs an ID/date/hashes and owners' acceptance
before the first campaign.

Use single-factor ablations then justified interactions. An invalid/inexecutable
combination is not a comparable measurement and gets no fabricated score.
Keep scripted providers, real models and human studies separate; fixtures establish
no autonomous behavior.

## Corpus and evidence

Preserve T01…T22 and both-domain variants where applicable. The plan's matrix is
an initial register, not executed-test counts. Establish valid same-precondition
controls before each injection. Cover injection/memory/delegation, post-approval
substitution, revocation/commit, new intent keys, crash/replay, direct paths,
secret/egress, cumulative effects, human approval, candidate/tool mutation and
tampered/rolled-back evidence.

Observe before/after service state, intent/authorization, consumed content,
commit order, receipts, actual egress and reconciliation. Git exit status proves
neither no effect nor atomicity with SQLite. Distinguish network attempts from
bytes actually received. Retain each candidate/TCB/configuration, seed/variant,
executor/argv, times/duration, original outputs, known/unknown cost, verdict and
coverage limits. Minimize sensitive data without erasing authorized originals.
Collection failure is incomplete evidence, never default success or unchanged retry.

## Analysis and verdict

Report distinct attempts, forbidden effects, success, false refusals, UNKNOWN/
recovery, p50/p95/p99 latency, cost and operator load per scenario/condition.
Preserve units and unknown cost. Adaptive attacks are not presumed independent;
binomial bounds apply only where assumptions hold. Zero observed failure proves
neither zero risk nor universal coverage.

Every refutation keeps its original counterexample and acknowledged handoff,
followed by correction and evaluation of the changed candidate. A mean score
cannot compensate a required failing criterion. Negative B2 comparisons are
published honestly. E3 remains experimental and bounded by evaluated versions,
assumptions and paths; no critical-deployment right follows. PA-13 retrospective
is still required.
