# French and English interfaces

Swarm keeps French as its default language and provides an English interface.
The browser and CLI choose their languages independently.

## Select a language

- Web: use **Langue / Language** in the navigation. The preference is stored in
  this browser. `?lang=en` and `?lang=fr` also set the preference.
- CLI: `swarm --lang en help`, or `export SWARM_LANG=en`.
  `--lang` overrides the environment variable. Only `fr` and `en` are accepted.
- Switching the web language reloads the page. Save edits first. Preparation
  drafts block this reload until pending changes have been saved or cleared.

## Translation boundary

`locales/en.json` is the shared catalogue. Its keys are the French source
strings. Unknown strings fall back to their source text. This includes technical
errors that have not yet received a reviewed translation.

Translate interface labels, help, explanations and known engine presentation
fields. Never translate user titles, objectives, criteria, prompts, documents,
reports, provider output, paths, IDs, commands, enum values or persisted state.
The language setting does not instruct a model to answer in another language.
JSON command output and HTTP data contracts remain unchanged.

In JavaScript, use `SwarmI18n.t(source, values)` for labels. Named placeholders
preserve substituted values literally. `SwarmI18n.engine(source)` is reserved for
known engine-generated descriptions; it supports catalogue printf templates.
Never apply it to arbitrary model output or whole API responses. Initial static
HTML is translated before application scripts run. Dynamic DOM content is not
scanned automatically.

In Go presentation code, use `uiText(source)` before formatting a message.
Do not localize errors where control flow or JSON contracts depend on them.
Do not translate persisted display labels or graph preference keys.

## Add or update a translation

1. Add the French source and English translation to `locales/en.json`.
2. Wrap the display literal in the appropriate translation helper.
3. Preserve placeholders, whitespace used in composition and command examples.
4. Run `npm run i18n:build` to regenerate `web/i18n-en.js`.
5. If terminal source changed, run `npm --prefix frontend run build:terminal`.
6. Run `npm test`, `go test ./...`, `make build`, then `npm run test:i18n-ui`.

The browser recipe uses an isolated fixture, starts no real agent and checks
both themes, locale switching, preservation of mission data, help, connection
forms and preparation drafts. Screenshots go to `test-results/i18n/`.
